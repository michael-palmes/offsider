# Apps

`offsider app info|launch|stop|open|install|uninstall|prefs|broadcast` acts on one app and nothing else on the device. Name it with `--app <bundle id or package>`; without one, Offsider takes `offsider.login.json`'s app, then a physical device's only pinned app (exit 64 with neither).

- `offsider app info --app <id> --device <DEVICE_ID> --json` reads the version (`appVersion`) and `build`, and on Android the `installer` (`com.android.vending` is Google Play, null for adb), `firstInstalled`, `lastUpdated`, `debuggable` and, from Android 13, `notifications` (`granted` or `denied`). An iPhone app installed from Xcode reads installer `developer`. Use it to prove the build under test is the one installed. Its JSON `untrusted` list names the app's own text.
- `offsider app launch --app <id>` starts the app as a tap on its icon does; `--restart` or `--cold` stops it first, for a cold start. JSON `start` is `cold` (a new process) or `warm` (it was running); Android adds `milliseconds` (`TotalTime`), `waitMilliseconds` (`WaitTime`) and `launchState`. For a cold-start comparison, run this with `--json`, then `logs --rn --app <id>` for that launch.
- `offsider app stop --app <id>` ends the app's process; `wasRunning` says whether there was one. An app extension is not the app. On Android this is Force stop, which also clears the app's notifications and alarms.
- `offsider app open '<link>' --app <id>` sends a deep link or universal link to that app alone, never a browser; quote the link so `&` and `?` survive your shell. `--restart` opens it cold. On Android and a simulator a link the app has no screen for, or that lands on a chooser or another app, exits 1 `link_not_handled`. On an iPhone or iPad exit 0 means only delivered (`linkHandled` is `null`), so `wait` for the screen. On a simulator iOS picks the app that claims the link, Offsider answers the `Open in` prompt only when it names that app, and checks the app is in front; on an iPhone or iPad the app receives it as an open-URL call, not as a tapped universal link. `intent:`, `file:`, `content:`, `javascript:` and `data:` links are refused (exit 64).
- Android only: `offsider app install <apk>` installs an APK, refusing one that does not declare `--app` (`package_mismatch`); `--app` defaults to the APK's own package on an emulator or a test device. `offsider app uninstall --app <id>` removes the app and its data. On a phone both need the app pinned by name: allowing any app is not enough.
- Android only: `offsider app prefs --app <id> --json` lists each shared preference file's key names and types. Values never leave the device, and no option asks for one. It needs a debuggable build: a release build exits 1 `not_debuggable`, and the fix is to install one.
- Android only: `offsider app broadcast <action> --app <id>` sends a broadcast to that app's own receivers (`--receiver .Class` for one), which is how to refresh a home-screen widget: send the action its provider declares. System actions such as `APPWIDGET_UPDATE` exit 1 `broadcast_refused`, listing the app's own actions; a receiver the app lacks exits 1 `receiver_not_found`. JSON `resultCode` is what the receiver set, and `receivers` lists those its manifest declares.
- `offsider airplane on|off --device <DEVICE_ID>` (Android; no value reads it) changes airplane mode, and `session stop` turns it off only if this command turned it on. Set by hand first, it stays.
- A person can allow these once in their rules rather than per call: `offsider init --print-rules` lists them under `allowOnce`. Each still reaches only allowed apps.
- `info` and `prefs` only read; the rest lock the device like input. After `launch` or `open`, wait for the screen you expect (`wait --id <id>`) before acting on it.
- On a physical device the app must be one its allowance permits: browsers, home screens, system apps and apps managed policy denies exit 1 `app_not_allowed` with nothing sent, also on a phone allowed for any app. A locked iPhone exits 7 `device_locked`: ask the user to unlock it.
