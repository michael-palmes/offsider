# describe-ui

## The summary

- `offsider describe-ui --summary --device <DEVICE_ID>` prints one line per on-screen node that has a label, id or value, such as `button "Save" id=save-button (170.7,313.3 61x34.3)` (role, label, id, value, then x,y and size). Use it to find `--id` and `--label` values for selectors and to confirm coordinates.
- `--summary` is `--flat --on-screen --labelled --format text --max-bytes 16384`. Combine the parts yourself when you need more: `--flat` (no nesting; each node has `index`, `parent` and `depth`, under `nodes`), `--on-screen`, `--labelled`, `--actionable` (controls only), `--fields role,id,label,value,frame`, `--format json|ndjson|text` and `--compact` (one-line JSON). A full screen can hold hundreds of nodes, many of them off screen, so reach for plain `describe-ui` only when you need the whole tree.
- `--summary` folds labels a parent already shows (`# folded N repeated labels` closes the output), and lists rows past an edge as one line per side, such as `[off-screen below] 34 items: id=rows-item-9 to id=rows-end`: scroll that way to reach them. `(+N inside)` after the count, as in `[off-screen below] 1 item (+12 inside): id=sheet-host`, says how many listed elements those items hold and hide.
- A screen a full-screen page covers is left out of `--summary` and counted at the end, past any truncation: `# beneath: "Products" (42 elements) under "Kettle"`. Its elements are beneath the page, so a tap there would land on the page; selectors prefer the page's own matches, and JSON still lists everything.
- It stops at 16384 bytes with a `# truncated: N more nodes` line; pass `--max-bytes 0` for everything, or narrow with `--actionable`. `# the device stopped listing nodes at its limit` means the Android tree itself is incomplete.
- `offsider describe-ui --point <X,Y> --device <DEVICE_ID>` inspects the element at a coordinate.
- Lines after the device line say what surrounds the elements, only when it applies: `# window: <title> (modal)` or `(system)` on Android when a dialog, a React Native `Modal` or a system window is in front (only its elements are listed; `(modal, empty)` when it spans the screen with nothing labelled or actionable, as React Native can leave its LogBox dialog), `# window: Save Password? (system)` on an iOS simulator when another process draws a prompt over the app (its buttons are not listed, so take a screenshot), `# keyboard shown` while a keyboard is up (dismiss it before tapping near the bottom; an iOS 27 simulator lists no keyboard element, so Offsider reads its key layout group, id `UIKeyboardLayoutStar Preview`, as role `keyboard`, and a hardware keyboard shows no header), and `# logbox: 2 logs` or `# logbox: inspector open` in a React Native debug build. JSON carries them as `context` (`window` with `empty`, `keyboard`, `logbox`).
- On an iOS simulator describe-ui also reads the element at the screen's centre once (the `probe` phase of `OFFSIDER_TIMINGS=1`) and compares it with the tree. `# presented: "Cancel" from PickerService` means another process draws over the app there, such as a system picker or a view an SDK presents, so the tree may still list the screen beneath (a system prompt is named by `# window: ... (system)` instead, never twice): the label is masked and cut to 40 characters, never a value or a secure field's text, and the process is its executable's file name. `# stale frame: id=sheet-host is listed off screen at (0, 10000) 402x874, but the screen's centre is inside it; check a screenshot` means a screen-sized view's frame is likely out of date, so trust a `screenshot` over its frame. A `wait` or `assert` that misses makes the same read once and adds what it found to its reason. JSON carries them as `context.presented` (`label`, `role`, `process`) and `context.staleFrame` (`id`, `label`, `frame`), null otherwise.
- On Android, `# hidden: 2 branches not visible to the user` counts subtrees the helper left out because Android marks them not visible, such as a list scrolled away, a sheet parked off screen or a panel slid aside with a transform. When the screenshot shows content the tree lacks, the app may be hiding it from accessibility. JSON carries it as `context.hidden`, null when the tree came from uiautomator or an older helper.

## What changed

After an action, `describe-ui --diff` prints only what changed since the previous command's tree: `added`, `changed ... (was: ...)` and `removed` lines, or the full view when most of the screen changed. After a tap it compares with the screen before the tap. `unchanged since tap 840 ms ago` means the screen matches that earlier tree exactly: the action had no visible effect yet, so wait or check the target rather than re-reading. Text only.

## JSON

- Without those flags the output is `{"version": 2, "platform", "device", "screen", "roots": [...]}`. Each node has `role`, `id`, `label`, `value`, `frame`, `enabled`, `state` (`checked`, `selected`, `focused`), `native` and `children`; every key is present, with `null` when unknown. `selected` is `true` or `false` on both platforms (from the Selected trait on iOS, and `null` there when Offsider had to read the tree without traits). describe-ui prints JSON by default and has no `--json`. `--point` returns the same envelope with the hit element as the only root.
- `role` is one of `application`, `window`, `group`, `other`, `button`, `link`, `menuItem`, `tab`, `tabBar`, `segmentedControl`, `text`, `header`, `image`, `progress`, `textField`, `secureTextField`, `searchField`, `textArea`, `switch`, `checkbox`, `radioButton`, `slider`, `picker`, `cell`, `list`, `scrollView` or `keyboard`.
- `native` keeps the platform attributes, such as the iOS `type` (`TextField`, `RadioButton`), `role` (`AXButton`) and `roleDescription`.
- Password and other secure fields read as bullets, one per character.
- `screen.orientation` is the shape (`portrait` or `landscape`) and `screen.rotation` the device's turn in degrees anticlockwise from portrait (portrait 0, landscape-left 90, portrait-upside-down 180, landscape-right 270), the same as `orientation --json` `rotation`. `screen.display.id` is `main`, or `cover` or `inner` on a foldable, and `screen.posture` is null unless the device folds.
- `--display <id>` fails with a hint when that display is not active (`guide foldables`).
