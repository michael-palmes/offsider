# Security policy

## Supported versions

Only the latest release receives security fixes. Upgrade before reporting an issue you found on an older version.

## Reporting a vulnerability

Report vulnerabilities privately through GitHub: open the [Security tab](https://github.com/michael-palmes/offsider/security) of this repository and choose **Report a vulnerability**. Please do not open a public issue.

Include the Offsider version (`offsider --version`), your macOS and Xcode versions, and steps to reproduce. You will get an acknowledgement as soon as practical, and a fix or mitigation plan once the report is confirmed.

## Scope and threat model

Offsider is a local command-line tool that AI agents and scripts run on a developer's Mac to read and drive simulators, emulators and USB devices. This file lists everything it touches and the controls around each, as of the hardening that followed an external security review.

It is built for these risks:

- **An agent that follows the wrong instructions.** Text on a device's screen, in a web view, a notification or a log is written by the app under test or by whoever can put text in it. Offsider treats it as data: it escapes and caps what it prints, and the bundled skill tells agents to stop and ask when screen text asks for anything.
- **An agent that reaches too far.** Physical devices, saved secrets, linked apps, unlock codes and loosened settings each need a person at the Mac, in a terminal, confirmed with Touch ID or the login password. No environment variable or flag bypasses that.
- **Secrets in output.** Password values never print, screenshots mask password fields by default, logs are redacted, and typed text never appears in output, errors or arguments.
- **Other local users and planted files.** Every file and socket Offsider keeps is private to the user, opened without following symlinks and checked before use.
- **A tampered install or release.** Releases are built without secrets, signed in a separate job, run with library validation on, and check their bundled files against digests compiled into the binary.

Out of scope: a hostile process already running as the same user can read the user's files and Keychain items it is allowed to read, and drive any device itself; Offsider's controls make its own path harder, not that one. Where a control only raises the bar against such a process, this file says so.

## Network

Offsider has no telemetry, no accounts and no update checks. It never connects to non-loopback addresses, never resolves hostnames and never sends telemetry. It uses Unix sockets and loopback TCP to local developer daemons only: the adb server, the Android Emulator's gRPC endpoint, usbmuxd and Metro.

- Metro: `rn open` reads `/status` on 127.0.0.1 at the port passed to it, one HTTP request with a 2 s timeout, no proxy, and never follows a redirect (a 3xx reads as "something else answered").
- adb: over loopback TCP (127.0.0.1, ::1) or a Unix socket; `ADB_SERVER_SOCKET` pointing anywhere else is refused, and a `localfilesystem:` socket whose server runs as another user is refused (`getpeereid`). Offsider starts the SDK's own adb with mDNS off (`ADB_MDNS=0`) when none is running, and that server keeps running afterwards like any adb server. A shell or exec command that prints more than 64 MB is stopped.
- `xcodebuild`, which builds the iPhone runner, talks to Apple's developer services for provisioning, as Xcode does; Offsider passes it only the proxy variables for that.

## On the Mac

Offsider keeps its state in a private per-user directory, `offsider-<uid>/` under the per-user temp directory from `confstr(_CS_DARWIN_USER_TEMP_DIR)`, which ignores `TMPDIR` (falling back to `$TMPDIR/offsider-<uid>/` when it cannot be used). It is mode 0700, owned by the user and checked on every use. Every file in it is 0600, written to a fresh file and renamed into place or created exclusively, and read only when it is a regular file owned by the user, opened without following symlinks and without blocking, so a FIFO planted in its place is refused rather than hanging a command.

- `locks/`: one file per device driven, holding only the holding command's pid, name and start time. The lock is advisory and never inherited by the processes Offsider starts. While `record-video` runs, a `<device>.recording` marker beside it makes `login` refuse to type.
- `trees/`: the last accessibility tree read from each device, named by the first 16 hex digits of a SHA-256 of the platform and device ID, so device names never reach a file name. It holds the tree as `describe-ui` prints it without the `native` attributes (no process IDs or class names), with password values already masked, plus the writing command, timestamps, the screen's size, rotation, display and posture, and a boot marker. It is capped at 1 MB, ignored from an earlier boot of the device, and deleted by the next command that writes to the cache once 10 minutes old, whichever device it belongs to. It serves `describe-ui --diff`, verify change lists and the tap guard, and is never sent anywhere. `OFFSIDER_TREE_CACHE=off` turns it off.
- `leases/`, `runs/`, `signins/`, `orientation/`, `displays/` and `unlock/`: lease records, evidence run records, sign-in records, Android auto-rotate records, foldable phone panels and failed unlock code markers, as the README describes. None holds a username, password, code or screen text.
- `logs/`: the emulator's output from `boot`, `boot-<avd>.log` (the AVD name made safe for a file name), emptied once it passes 5 MB.
- `ios-devices/<UDID>/` and `sessions/`: iPhone and iPad runner and broker records and logs, and each Android device's warm helper socket and log, `android-<hash>.sock` and `.log`, named by a hash of the serial (below).
- The HID broker's per-user Unix socket under `$TMPDIR/offsider-hid-<uid>` (below).

Outside it:

- `~/.config/offsider/allowed-devices.json`, the allow-list of physical devices (below). The folder is 0700 and the file 0600, written atomically under a lock, read with a 64 KiB cap. Its path comes from the password database (`getpwuid_r`), never `HOME` or `XDG_CONFIG_HOME`; a `~/.config` symlink is followed once, and only to a folder the user owns that others cannot write.
- The login Keychain: saved test users, unlock codes and the allow-list's seal (below).
- `~/Library/Caches/offsider/runner/`: the iPhone runner's build (below).
- Files you ask for. Screenshots, diffs and recordings are written 0600 to `--output` or to a generated name in the current directory. A generated name never replaces a file (a taken name gets ` 2`, ` 3` and so on), and the device name in it loses separators, control, bidi and zero-width characters. `--output` naming an existing file replaces it whole, through a sibling temporary file, `fsync` and rename, only when it is a regular image or video file the user owns; a link, a directory or another kind of file is refused, and nothing is deleted first. `record-video` writes into a private 0700 staging folder beside the target.
- Evidence run folders, after `offsider run start <dir>`: created 0700 with a `.gitignore` of `*`, holding `run.json`, `manifest.ndjson`, a lock file and the captures, each 0600. A run whose recorded folder is no longer a real directory the user owns that others cannot write, holding that run's `run.json`, is refused (`run_unavailable`).
- `type --file` and `batch --file` read one regular UTF-8 file of at most 64 KiB, judged after symlinks resolve, opened without blocking (a FIFO is refused) and checked to be the file that was resolved. Files under `~/.ssh`, `~/.aws`, `~/.config`, `~/.gnupg`, `~/.docker`, `~/.kube`, `~/Library/Keychains`, `~/Library/Application Support/offsider` and `/etc`, and names such as `.env`, `.env.*` (not `.env.example`), `.netrc`, `.git-credentials`, `.npmrc`, `.pypirc`, `id_*`, `*.pem`, `*.p12` and `*.key`, are refused unless `--allow-path` is passed. Every read prints the resolved path and size to stderr.
- `offsider init` writes its skill to `~/.claude/skills/offsider`, `~/.agents/skills/offsider` or the directory you pass with `--dest`.

Processes Offsider starts get an allow-listed environment, never the caller's whole one: a base set (`HOME`, `PATH`, `TMPDIR`, `USER`, `LOGNAME`, `SHELL`, `LANG`, `LC_*`) plus, per kind of child, the Android SDK and AVD locations for the emulator (with `ADB_MDNS=0` and crash reporting forced off), the SDK, key and socket settings for `adb start-server` (with `ADB_MDNS=0`, never `ADB_TRACE`), `DEVELOPER_DIR` and `OFFSIDER_*` for Offsider's own iPhone brokers, the SDK, key and adb server settings and `OFFSIDER_*` for its Android brokers (with `ADB_MDNS=0`), and `DEVELOPER_DIR`, `TEST_RUNNER_*` and the proxy variables for `xcodebuild`. Detached children start in their own session with `POSIX_SPAWN_CLOEXEC_DEFAULT`, so they inherit no file descriptor but stdin (`/dev/null`), stdout and stderr; their logs are opened by Offsider without following symlinks, and must be regular, owned by the user and single-linked.

`doctor` lists your other running `offsider` processes by reading each one's arguments and keeps only the subcommand and the `--device` value: never typed text, other arguments or other environment variables.

## What reaches your agent

Whatever Offsider prints reaches your agent, and from there whatever it sends to its model provider. Offsider itself sends nothing.

- **The screen, as text.** `describe-ui`, selectors, `wait`, `assert`, `--verify` change lists and errors carry the screen's labels, values, ids and window titles. Password values read as bullets, one per character. Control (C0, DEL, C1), bidi, zero-width, soft hyphen, line and paragraph separator, interlinear annotation, tag and variation-selector characters in any of that text print as JSON-style escapes such as `\u001b`, so an OSC 52 clipboard write, hidden tag text or a payload smuggled in variation selectors shows inert (a lone U+FE0E or U+FE0F after a visible character, as every emoji label carries, stays as it is). A window title holding one is quoted, each string is cut at 500 characters or 500 scalars (`…(+N)`), so a flood of combining marks cannot stretch one character, and an `Error:` line's continuation is indented, so screen text cannot start a line of its own. The `Try:` line under it holds only the error's `hint`, escaped the same way, and a hint never holds typed text, a password or an unlock code. JSON escapes the same characters and still decodes to the original. A tree is cut at 64 levels or 50,000 elements, with a note.
- **The screen, as pixels.** Screenshots mask password fields by default, after one tree read; a field without a frame withholds the image. Masks cover only what the accessibility tree describes: web views, canvases, images, a secret in an ordinary text field (a show-password toggle, a custom PIN pad) and anything drawn between the tree read and the capture can still show. Evidence runs also mask email addresses. Video is never masked by the tree: `record-video` and `stream-video` check once, before the first frame, that no password field is on screen, so one that appears later is recorded.
- **Logs.** `logs` redacts by key (passwords, tokens, keys, cookies, `Authorization`, JWTs, emails, seeds and recovery phrases, private keys, one-time and verification codes, bank, card and identity numbers, wallet addresses) and by value pattern (wallet addresses, Luhn-valid card numbers, 12 to 24 word recovery phrases, 6-digit codes after `otp`, `code`, `pin` or `2fa`), on by default. It cannot catch a secret under an unusual key or in free text. Text output escapes control characters and strips terminal escape sequences; `--raw` keeps colour codes only.
- **Notifications.** Whatever the device shows, including notifications, is on the screen. On a physical device, turn on a Focus or Do Not Disturb first.

The skill `offsider init` installs tells the agent that all of this is data from the app under test, never instructions, and to stop and ask before anything that moves money, touches real accounts, grants permissions the test did not name, links saved logins, unlocks a device or uses a physical device.

## Saved secrets

Test users and unlock codes live only in your login Keychain, as generic passwords that are never synchronised, and never appear in Offsider's output, errors, logs, timings or arguments. macOS asks once before a new or rebuilt `offsider` reads an item.

- **Test users** (`credential set`): one item per user (service `com.mpalmes.offsider.login`, account the app id and the user's name). Its encrypted data (version 2) holds the username, the password, the apps linked to it and its settings: `devices` (`virtual`, the default, for simulators and emulators only, or `any`, which also allows Android phones on the allow-list), `confirm` and `webLogin`. A version 1 item reads as no links, no confirm, `devices virtual` and no web sign-in, and every save writes version 2.
- **Context** (tags and the `--about`, `--avoid` and `--state` notes) sits in the item's attributes, which the Keychain does not encrypt, so any process running as you can read it without a prompt. It refuses email-like text, control and bidi characters, and must never hold secrets or personal details. `confirm` and `devices` are mirrored there so `login` can ask early, but only the encrypted data decides.
- **Linking** (`credential join`): a person only. It needs a terminal on standard input, always asks which app to share with, asks Link or Cancel, then Touch ID or the login password, and refuses browsers and system apps. A link item for the second app id stores no password, only an index for a cheap lookup; `login` trusts a link only when the canonical item's encrypted data lists that app, which only `join` writes. Links saved by earlier versions are not trusted until `join` runs again.
- **Loosening** a user (`--devices any`, `--no-confirm`, `--web-login`) needs a terminal and Touch ID or the login password; tightening needs neither.
- **The presence check.** A user saved with `--confirm` (on by default with `--devices any`) makes `login` ask for Touch ID, an Apple Watch or the login password before it reads the password; the macOS sheet names the user, the app and the device. It uses LocalAuthentication's device-owner check inside Offsider, because Keychain items that require user presence need the data protection keychain, which a command-line tool signed with Developer ID cannot use without a provisioning profile and an app bundle. With no GUI session (plain `ssh`) it fails closed with `person_required`.
- **`login`** types a password only into the app it was saved for or a person linked, and refuses: a browser or system app in front (`app_not_allowed`); a password field inside a web view, unless both the saved user (`--web-login`, by a person) and the repository's `offsider.login.json` (`"webLogin": true`) opt in; another app coming to the front before the password or before the submit tap (`foreground_changed`, recomputed from the tree it just read); a Cloudflare Turnstile widget (`turnstile_required`); a physical iPhone or iPad; and an Android phone that is not allowed or a user without `devices any`. On an iOS simulator, a web view is recognised by a web-area role or by a password field drawn by another process; with neither signal it is treated as native. Offsider never taps Turnstile: `turnstile` only reads its state, and the timing jitter it once had is gone.
- **Sign-in records** (`signins/`) hold the app, the app in front, the user's name, the platform, a stable device key, the time and a boot marker, never a username or password.
- **Unlock codes** (`unlock-code set`): service `com.mpalmes.offsider.unlock-code`, account the phone serial or AVD name. `set` needs a terminal; `set --stdin` still reads the code from a pipe but confirms on `/dev/tty` and with Touch ID or the password. On a phone it needs the phone to be allowed first. `wake --unlock` types the code once, as key events through the UiAutomation helper's authenticated socket, and only into a focused password field inside System UI's lock screen; without the helper it types nothing (`helper_unavailable`). It never becomes a process argument on the device. Before the first key, an empty `unlock/device-<id>.failed` marker is written (a write failure stops the command), and it is cleared only once the device is seen unlocked, so a failed code is never typed again until the device is unlocked by hand or the code is saved again.
- **The allow-list seal**: a login Keychain item (service `com.mpalmes.offsider.devices`, account `allowed-devices`, never synchronised) holding the SHA-256 of the allow-list.

## Simulators

- Xcode's private simulator frameworks (CoreSimulator, SimulatorKit and related) load at runtime from the selected Xcode. Offsider first resolves `DEVELOPER_DIR` or `xcode-select` with `realpath`, requires `<name>.app/Contents/Developer`, and checks that the app satisfies `anchor apple`, or, for Xcode from the Mac App Store, whose app the store signs, Apple's Mac App Store signature on `com.apple.dt.Xcode` (its main executable and `Info.plist`, about 40 ms, once per process), refusing with `xcode_unusable` otherwise; `doctor` reports it as `xcode.trust`. The check proves the app's main executable and `Info.plist` are Apple's; library validation is what stops a non-Apple framework loading into the signed binary. `devicectl` and `xcodebuild` run only from a trusted Xcode too.
- Before each private method it calls through a cast, Offsider compares the method's type encoding with the one it was built for, and fails with `xcode_unusable` rather than call a changed method.
- Simulator HID input (touches, key presses, buttons and text) goes to the simulator named with `--device`, through a broker on a per-user Unix socket under `$TMPDIR/offsider-hid-<uid>`. The broker rejects connections from any other user before sending them anything, refuses a request of more than 4,096 primitives, a delay that is not finite or is outside 0 to 10 s, or delays over 25 s together, and when its client goes mid-request it stops within 100 ms and lifts any touch left down.

## Android emulators and phones

- **The helper.** A small helper, Offsider's own code built from the Java source in this repository, reads the screen through UiAutomation and can inject input. Its dex is pushed 0600 into a 0700 folder made by the shell user, `/data/local/tmp/offsider-push-<pid>`, then moved to its content-addressed name, `offsider-helper-<hash>.dex`, made 644 and the folder removed, so it is never writable by others. On every start the start script checks the copy's SHA-256 against the manifest (`sha256sum`), and only on an image without `sha256sum` falls back to its size. The Mac's copy is checked against the digest compiled into Offsider. The helper runs with `app_process` as the shell user, listens on a randomly named local socket, accepts one connection only from the shell or root user and only when the first message carries a random token printed only on the shell stream that started it, then stops listening. It exits when that connection or its shell closes, or after 10 s without a request (30 s for a warm helper, whose broker pings it every 2 s). While it runs it holds Android's single UiAutomation slot, and the device reports an accessibility service as enabled. When it cannot run, a temporary `uiautomator` dump under `/data/local/tmp` is read and deleted instead.
- **The warm helper.** On an emulator, and on an allowed USB phone only with `OFFSIDER_ANDROID_SESSION=on`, the helper outlives the command, so the next one skips its start and the wait for a quiet screen. A broker keeps it: `offsider` started detached in its own session, holding the helper's start shell and its one connection, so the token stays in the broker's memory and never reaches a disk. Commands reach the broker on a 0600 Unix socket in `sessions/`, which refuses other users (`getpeereid`), serves at most 8 commands at once and passes their requests to the helper one at a time; it refuses `quit`, never sends input whose command has gone or that waited over 4 s behind another command, and gives up on the helper when a command's own timeout passes, counted from when its request arrived. It stops 60 s after the last command (`OFFSIDER_ANDROID_SESSION_IDLE`, at most 3600), on `offsider session stop`, when the helper misses its ping, or at its next idle moment once 12 hours old, and stopping it ends the helper, which frees the slot. Until then Appium, Maestro, `uiautomator`, instrumentation tests and Layout Inspector cannot connect, and apps can see an accessibility service enabled. A command that reads the screen another way (`OFFSIDER_ANDROID_TREE=uiautomator`, `OFFSIDER_ANDROID_SESSION=off`, a phone without `on`) stops Offsider's own warm helper on that device first, once no other command is using it, and removing a phone from the allow-list stops its one. Passwords and unlock codes typed through the helper pass through the broker's memory and are never logged. For an emulator with one display it also keeps, in memory only, the device states and display list a command read, which later commands reuse instead of reading them again. A process running as the same user can reach the broker, as it can reach adb itself. `OFFSIDER_ANDROID_SESSION=off` keeps one helper per command.
- **Typing secrets.** A password from `login`, and any text typed into a focused password field without gRPC, goes through the helper as key events, never as an `input text` command that other shell-user processes could see in the process list; without the helper nothing is typed. A clipboard paste is refused for a password field and for a field whose focus cannot be read. Over gRPC, non-ASCII text is pasted through the emulator's clipboard, which is restored afterwards; whether the emulator's clipboard sharing copies a paste to the Mac's pasteboard has not been checked.
- **gRPC.** The emulator's endpoint on loopback is authenticated with the token from the emulator's discovery file, or with a short-lived JWT: Offsider keeps the private key in memory and writes only the matching public key to the emulator's `jwks` folder, deleting it when the command ends; a key left by a killed command is removed by the next one.
- **Booting.** `offsider boot` starts the SDK's emulator with `-no-metrics`, never `-port` or `-grpc`. `--emulator-arg` accepts only an allow-list of flags that shape the device or its rendering, each value checked; flags that open a listener, connect out, read a host path or send metrics are refused, as are Offsider's own flags and `@name` tokens. `-camera-back` and `-camera-front` take only `emulated` or `none`, so an agent cannot see through the Mac's camera; an AVD's own `config.ini` can still name a webcam. Offsider never uses Google's Android CLI and never bundles adb.
- **State that persists.** `stay-awake` writes the `stay_on_while_plugged_in` global setting; `wake` sends `KEYCODE_WAKEUP` and `wm dismiss-keyguard`; `permission`, `status-bar`, `appearance`, `content-size` and `orientation` change settings that outlive the command.
- **Phones.** A USB phone is refused until a person allows it (below). An allowed phone's setters change the phone itself: `status-bar override` and `stay-awake on` say so with the undo command, and `permission ... all` is refused, since it would reach SMS, the call log and location. When a browser or system app is in front (Settings, System UI, browsers, Gmail, Messages, Play Store, Google Play services, Photos, Contacts, the dialer, the permission controller, the package installer, Wallet, Authenticator), or the app in front cannot be named, screen reads, screenshots, video, typing and a command's first input are refused (`app_not_allowed`); buttons are not, so a phone can always be sent home. The notification shade and quick settings are not a resumed activity, so they are not detected. Wi-Fi and TCP adb connections are refused, as is a USB device reporting an emulator's serial. Offsider never sets `adb reverse`.

## Physical devices: the allow-list

- Every command that names a physical iPhone, iPad or Android phone checks the allow-list first and refuses with `device_not_allowed` (exit 7), sending the device nothing: an iPhone is refused before any `devicectl` call, a phone after reading only the adb server's own device list. `list-devices` hides such rows unless `--physical` is passed. A physical device must be named with `--device` on each command; `OFFSIDER_DEVICE` never names one. Each command that drives an allowed device prints one line to stderr naming it, its expiry and how to withdraw it.
- `offsider device-access allow` is the only way onto the list. It needs a terminal on standard input (without one it is `person_required`), explains what it grants, lets a person choose the device, its team, the app to pin and the expiry from menus, shows a summary, then asks for Touch ID or the login password. Building those menus adds two local reads. The team menu lists the code-signing identities in the login Keychain: identities only, never private keys, and with no prompt. The app menu sends one installed-apps query to the chosen device, only after the person picked it in the menu and before it is allowed; a failed query falls back to typing an app id. Deny-listed apps and apps outside a managed ceiling are not offered. A device passed with `--device` also needs the last four characters of its ID typed, since that id may have been pasted from an agent; a device chosen from the menu does not. Entries expire (12 hours by default, at most 30 days unless `never`), can pin the apps Offsider may drive, and for an iPhone or iPad can record the team that signs its runner. The parser is strict, so an older Offsider refuses a list holding a team. `remove` needs no terminal, and on an iPhone or iPad also stops its runner and session broker.
- The list is sealed: `allow` and `remove` store the file's SHA-256 in the login Keychain, and an edit made any other way, or a missing seal beside a non-empty file, refuses every device until a person runs `allow` again. This turns a quiet file edit into a deliberate Keychain write; a hostile process running as the same user can still delete and re-add the item.
- Managed preferences in the domain `com.mpalmes.offsider`, honoured only when forced by a configuration profile, set a ceiling an administrator controls: `allowPhysicalDevices`, `allowedDeviceIDs` and `allowedBundleIDs`. A forced key of the wrong type refuses every physical device. Both the managed ceiling and the user's list must allow a device; only the managed preference is beyond a process running as the user.
- The list, the seal and managed preferences are read only when a command names a physical device, once per process, and never cached on disk.

## iPhones and iPads

- **Connection.** USB only: only a wired transport passes, and before each input batch usbmuxd must still list the device on USB. Offsider never pairs a device, never accepts a prompt on it and never types a passcode.
- **One app.** Each command drives one app: `--app`, else `offsider.login.json`'s `bundleId`, else the allowance's only pinned app. It must not be a browser or system app and must be within the allowance's apps and any managed `allowedBundleIDs`. Before each screenshot, broker or video frame (at most every 2 s within one command), each input batch and each detached touch, the runner checks with XCTest's own active-app lookup that the app is in front, and the command stops with `app_not_allowed` before reading or touching the screen otherwise.
- **Android pins.** An Android phone's allowance can pin apps too (the app step of `device-access allow`, or `--app <package>`), narrowed by any managed `allowedBundleIDs`: with a non-empty set, a screen read, screenshot, video frame or input (buttons excepted) with another app in front fails with `app_not_allowed`, naming the allow command, or saying the managed ceiling cannot be overridden. With no pins and no ceiling the phone is driven in any app but a browser or system app.
- **The runner.** The accessibility tree comes from a small XCUITest runner app built from source bundled with Offsider into `~/Library/Caches/offsider/runner/` (0700). Each source file copied into the cache is checked against the digests compiled into Offsider.
- **Its team.** It is signed only by the team in `OFFSIDER_IOS_TEAM_ID` or the one a person recorded in `device-access allow`, by picking it from the menu of the login Keychain's signing identities or typing it (`--team` in scripts); Xcode's signed-in team is never picked silently, only by a person in that menu. Its bundle ids are `<prefix>.runner` and `<prefix>.runner.uitests`, with the prefix from `OFFSIDER_IOS_RUNNER_PREFIX` (default `com.mpalmes.offsider`, validated). Normal builds never let Xcode register a device with the team; only `offsider runner build --device <UDID> --register-device`, which needs a terminal on standard input and output, does.
- **Its products.** After a build, `products.json` (0600) records the device, team, prefix and the SHA-256 of each product. Before each session starts, the products are hashed again, and the host app, the runner app and the `.xctest` bundle must satisfy `anchor apple generic and certificate leaf[subject.OU] = "<team>"` with their resources validated; otherwise the build is deleted and rebuilt once, then refused.
- **Running it.** It is launched detached with `xcodebuild test-without-building -quiet`, listens only on the device's loopback with a token per session, and is reached only through usbmuxd (`/var/run/usbmuxd`). Offsider's session record (pid, port and token, 0600), `runner.log` and result bundles live under `ios-devices/<UDID>/`; the token is never printed, and result bundles are deleted when a session stops or an exited one is forgotten.
- **The session broker** (Xcode 27) holds the device's CoreDevice screen stream, its UniversalHID touchscreen and keyboard and its hardware button socket. It listens on a 0600 Unix socket in `sessions/` and refuses other users. It serves at most 8 clients at once, drops a client that is silent for the idle timeout or takes more than 10 s to send a started request, refuses a request with more than 4,096 steps, a wait that is not finite or is outside 0 to 30 s, or waits over 60 s together, caps swipes at 1,000 steps and 30 s, refuses frame sizes over 16,384 pixels a side, and presses only the home, lock, side and Siri button usages. Its screen stream reaches the Mac only through CoreDevice's USB tunnel, and the device shows its screen-sharing indicator while it runs.
- **Lifetime.** The runner and the broker stop after `OFFSIDER_IOS_RUNNER_IDLE` and `OFFSIDER_IOS_SESSION_IDLE` seconds without a request (default 300, at most 3600). A runner session older than 12 hours is restarted on its next use, and a broker older than 12 hours stops at its next idle moment.
- **The developer disk image.** Any device command's `wake` step asks CoreDevice for `ddiServices`, which mounts a missing developer disk image, and `doctor --fix` mounts one too; both happen only on an allowed device named with `--device`.
- **What stays.** `session stop` stops the broker and the runner and clears the screen-sharing indicator; the runner apps stay installed and the cache stays. `session stop --clean` (or `runner stop --clean`) also uninstalls `<prefix>.runner.uitests.xctrunner` and `<prefix>.runner`, and deletes this device's runner builds, `runner.log` and the broker's log. What only the Apple developer site (Certificates, Identifiers & Profiles) removes stays in your team: the runner's provisioning profile, its App IDs and the device's registration.

## Release integrity

- Releases are built by `.github/workflows/release.yml` in separate jobs. The build job holds no secrets: it checks the tag's signature against `main`'s `.github/allowed_signers` and that the tag is on `main`, builds the binary, the idb frameworks and the runner check, and packs an unsigned payload with its SHA-256. A signing job in the protected `release` environment, on a fresh runner, checks out the tag commit, verifies the payload's digest, signs and notarises it, and never builds or runs it; the signing keychain and the notary key are removed as soon as each is used. A verify job on another fresh runner, with no environment, unpacks the signed archive, verifies the signatures and notarisation and runs the Homebrew gate. Only then is the release published with its `SHA256SUMS` and a GitHub build provenance attestation.
- Release binaries are signed with a Developer ID certificate, use the hardened runtime and are notarised by Apple. Their entitlements, in [entitlements.plist](entitlements.plist), are empty: library validation is on, so the binary loads only frameworks signed by the same team or by Apple. Ad-hoc builds for local rehearsals use [entitlements-adhoc.plist](entitlements-adhoc.plist), which disables library validation because an ad-hoc signature has no team; `scripts/release.sh` refuses to sign a release with a file that disables it.
- The SHA-256 of every file in Offsider's resource bundle (the Android helper's dex and manifest, the skill, the guide topics and the runner's source) is compiled into the binary at build time. A file that differs is refused with `install_damaged`. Replacing the binary itself loses its Developer ID signature.
- The [README](README.md#verified-tarball) shows how to check `SHA256SUMS` and the attestation, with `--signer-workflow` and `--source-ref` pinning it to the release workflow and the tag.
- The Homebrew formula is updated only through a pull request on the tap, opened by a GitHub App with access to that repository alone, and merged by auto-merge only after the tap's own checks pass.
- A pull request that changes `.github/allowed_signers`, `.github/CODEOWNERS`, the release or signers workflow, `scripts/release.sh` or an entitlements file must have its head commit signed by a key in the base branch's `allowed_signers` (the `Protected paths signed` check, which runs the base branch's copy of its workflow).
- The idb frameworks are built from the [michael-palmes/idb](https://github.com/michael-palmes/idb) mirror at a pinned revision that `scripts/build.sh` verifies before building, and Swift package versions are resolved strictly from `Package.resolved`. The Android helper's dex is rebuilt from its source with a pinned toolchain and compared with the committed copy in CI.
- One maintainer holds admin rights on the repository. An admin account takeover could still change its rules; a hardware security key for the account and for tag signing are the backstops.
