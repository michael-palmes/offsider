# Doctor and troubleshooting

`doctor` checks Xcode (`xcode.trust` passes for an Apple-signed Xcode in `/Applications`, warns for one elsewhere or chosen through `DEVELOPER_DIR`, and fails, skipping the framework checks, when the developer directory is not inside an Apple-signed Xcode; `xcode.private-api` fails when a private method Offsider calls changed type in this Xcode, so Offsider will refuse that call, and warns when CoreDevice is newer than the last version tested), Device Hub, CoreSimulator, HID settings, booted simulators and simulator crash loops, plus the Android SDK and adb server when an SDK is installed. With `--device` it checks one device instead: a simulator's state, Resize Mode, dtuhidd, HID transport, accessibility and recent crashes; an Android device (below); or an iPhone or iPad's `ios-device.*` checks (below). `--json` prints one object, and exit codes 3 and 4 mean warnings and failures.

Every report ends with the host: `host.load` (warns when the 1-minute load passes 4 per CPU), `host.disk` (free space in your home folder's volume: warns under 10 GB, fails under 2 GB) and `host.sessions` (other Offsider commands of yours, by subcommand and device only), then `install.bundle`, which reads every file bundled with Offsider through the digest compiled into the binary and fails, naming the first file that differs, when the install was changed (`brew reinstall offsider`), `install.skill`, which passes when every installed Offsider skill matches this version, warns `Run offsider init to update it.` when one differs (an agent, which has no terminal for `init`'s picker, is told `offsider init --client <client>` for each), and skips when none is installed, and `install.rules`, which warns `Run offsider init --rules-only.` when Claude Code or Codex is installed without Offsider's permission rules or with an older one since replaced, and skips when neither is. Without `--device`, a report with exactly one booted simulator or emulator ends with `Next: offsider doctor --device <ID>`. A person at a terminal sees a spinner while it checks, then a 🩺 header with the Xcode version and counts, the checks under This Mac, Android and the device as `✓`, `!`, `✗` or `-` rows, a `Fix` command under each warning or failure, and a closing line such as ❌ `1 failure · 1 warning` or ✅ `No problems found`, with the `Next` command on stderr. `--json` adds a top-level `host` object (`loadAverage`, `cpuCount`, `memoryGB`, `diskFreeGB`, `diskPath`, `sessions`), and with `--device`, `device.lease` reports any lease.

`--fix` applies safe fixes only: on Android, starting an absent adb server with `ADB_MDNS=0` (never when `--device` names a simulator); on an allowed iPhone or iPad named with `--device`, mounting the developer disk image.

For a physical device, `device.policy` comes first. A device no one allowed gets one failing `device.policy` check, with the `devices add` command as its hint, and no device checks run (`--fix` touches nothing); an allowed one passes it with its expiry. `doctor --device emulator-<n>` fails `device.policy` the same way when that serial is a USB device, or when adb cannot list devices to tell. `--json` adds a `policy` object for a physical device (`platform`, `id`, `allowed`, `refusal`, `expires`, `apps`, `managed`).

## Simulators

A simulator can fall into a crash loop after boot, with macOS showing a "quit unexpectedly" dialog for each crash. `doctor --device <UDID>` reads the crash reports macOS wrote in the last 10 minutes (only their header and process name, never paths or stack frames): `simulator.crash-loop` warns at two to four crashes of one process and fails at five or more (a busy host sees a few daemon crashes without a loop), printing `xcrun simctl shutdown <UDID> && xcrun simctl erase <UDID>` without running it. Erasing removes the simulator's apps and settings. Plain `doctor` lists every simulator with five or more crashes of one process as `simulators.crash-loop`, and `test-runner.sh` refuses to start on a simulator in a crash loop.

Simulator input goes through a warm input session ([details](input.md#simulator-input-session)). When input seems ignored after a simulator restarted or misbehaved, `offsider session stop --device <UDID>` closes it, and the next command opens a fresh one; `OFFSIDER_SIMULATOR_SESSION=off` opens one per command.

After an app crash and relaunch, a simulator can return an empty accessibility tree while the app is plainly on screen. When `describe-ui` still reads an empty tree after its retries, it checks the simulator's `launchctl list` and warns when an app is running, and `doctor --device <UDID>` fails `simulator.accessibility` with `<bundle> is running (pid N) but its accessibility tree is empty`. Both print the fix: relaunch the app with `xcrun simctl terminate` and `launch`, then, if the tree stays empty, reboot the simulator. No simulator service restart was found that reliably brings the tree back, so `doctor --fix` does not try one.

## Android devices

`doctor --device <serial or AVD>` runs read-only Android checks (host checks only, no Xcode checks): the SDK, adb and its server (on loopback, and whether its mDNS discovery is off), the emulator package and the bundled helper; then the device's state and system image (an emulator without `arm64-v8a` is told to use one; a phone, whose image cannot change, is called untested), its RAM (`android-device.memory` warns under about 2.75 GB, with the `boot --memory 4096` hint), its screen and lock screen, and whether it waits for its first unlock since boot (`android-device.lock` fails then, with the same hints as `boot`, and warns on an unlocked device while its saved code is wrong or unconfirmed; `device.lock` in `--json` has the same fields as `boot --json`; on Android 9 and older, which do not name the credential, it reads whether one is set from the keyguard and says `unlock-code` takes a PIN or password only); stay awake; its gRPC endpoint with the auth mode (never the token); the UiAutomation slot and any accessibility service; one helper start with its times; and any Metro reverse (shown, never changed; one `rn open` set is marked, and `session stop` removes it). The helper start holds UiAutomation for about half a second, so it is skipped while another Offsider helper runs.

On a USB phone, the checks come from its row in adb's device list, the emulator gRPC check is skipped (the report says why), and `doctor` adds whether this Mac's adb authorisation lapses (Developer options > Disable adb authorization timeout) and whether automatic system updates can restart it. `doctor` never kills a process, restarts the adb server or changes a setting.

## iPhones and iPads

`doctor --device <UDID>` runs the `ios-device.*` checks: `xcode`, `coredevice`, `listed`, `transport`, `pairing`, `developer-mode`, `ddi`, `tunnel`, `lock-state`, `hid`, `ui-automation`, `session`, `usbmuxd` and `runner-signing` (which passes for a team from `OFFSIDER_IOS_TEAM_ID` or the allowance, and warns when only Xcode's signed-in teams exist).

- `ios-device.hid` opens the HID button socket and round-trips a barrier on it.
- iOS does not report the UI Automation setting, so `ios-device.ui-automation` is skipped with the Settings path unless the unlocked device refused input.
- `ios-device.session` reports the session broker and its screen stream, and is a skip when none is running: doctor never starts one.
- `ios-device.usbmuxd` checks that usbmuxd lists the device on USB: usbmuxd can stop listing a wired device that `devicectl` still sees, until the cable is replugged.
